API reference

The functions behind the command line. Names marked TangoKalender. aren't exported.

Site and build

TangoKalender.SiteConfig — Type
SiteConfig

Settings for one city's site (site.toml):

  • slug: short id ("oslo"), name: site name in titles and feeds ("Tangokalender | Oslo"), city: the city (default venue.city, texts, geocoding).
  • site_url: where the site is published, without a trailing slash; may have a path (https://tangokalender.github.io/bergen). Every absolute URL derives from it.
  • repo_url: the data repo on GitHub; the issue forms (…/issues/new?template=…) are there.
  • map_center (lat, lon) and map_zoom: the map view when no event has a position.
  • countrycodes (and optional viewbox, "lon1,lat1,lon2,lat2"): Nominatim search limits for geocode.
  • og_image: link-preview image file (absolute path; site.toml gives it relative to itself), nothing = the package's generic image.
  • texts: per language (nb/en/es), UI strings that replace the package's _T entries.

TangoKalender.write_site — Function
write_site(dir, events; today=Dates.today(), venues=Dict(), kwargs...) -> files

Write the whole static site. Per language (Norwegian at the root, English under en/, Spanish under es/, same file names): the three views (index.html = compact list, uke.html, kort.html), one page and one .ics per event (arrangement/<id>/index.html, arrangement/<id>.ics), kalender.ics, rss.xml, legg-til.html, om.html, bygg-inn.html and the embeds (embed/). Once, at the root: events.json, the old for-ki.html redirect, the spreadsheet template, llms.txt and the schemas. site (see load_site) gives the city, name and URLs; venues (see load_venues) gives map positions. kwargs go to render_events_html.

source
TangoKalender.render_events_html — Function
render_events_html(events; view="cards", site=false, lang="nb", …) -> String

One calendar page. view is "cards", "compact" (dense list grouped by day), "week" (one week at a time) or "map" (map of the venues above the compact list; positions from the venue cache, see write_site(…; venues)). site=true (used by write_site) adds the view tabs, links to event pages, the feed links and the language switcher. lang is "nb", "en" or "es" (see src/i18n.jl).

Bulk edits

TangoKalender.Event — Type
Event

One event as a struct. JSON keys are the field names, except $schema (field schema) and end (field end_). Read and write files with read_event/write_event; change fields with set_path.

source
TangoKalender.read_event — Function
read_event(file) -> (event::Event, keys::Vector{String})

One event file as an Event, plus its keys in file order (so write_event can keep the order and the absent keys). Throws ArgumentError for keys the schema does not know.

source
TangoKalender.write_event — Function
write_event(io, e, keys)

Write e as save_events does (4-space indent, trailing newline): first the keys in keys (the order the file had), then any other field that is not null. A file read with read_event and written back unchanged is identical.

source
TangoKalender.set_path — Function
set_path(x, path, raw) -> copy of `x`

Set the field at path (JSON keys, e.g. ["venue","name"]) to raw, read as JSON or else as plain text and converted to the field's type. A null object on the way is created first (setting venue.name on an event without a venue gives a venue with only a name).

source
TangoKalender.check — Function
check(e::Event) -> problems

The schema rules for one event, checked on the struct (no JSONSchema, so it compiles trimmed). The app also runs the full validate_event_tree.

source
TangoKalender.check_event_tree — Function
check_event_tree(root) -> [(file, message)]

validate_event_tree on structs: every file reads as an Event and passes check, ids are unique and files are at their event_path. Used by the trimmed app, which has no JSONSchema.

source
TangoKalender.find_events — Function
find_events(terms; root="events", from=today(), until=nothing) -> [(file, event, keys)]

Events under root that match all terms (strings or SearchTerms), sorted by start. from drops events that ended before it (nothing keeps past events); until drops events that start after it.

source
TangoKalender.edit_events — Function
edit_events(terms, edits; root="events", from=today(), until=nothing, dry_run=false, tree_check=validate_event_tree) -> (edits, written, errors)

Apply edits ("key=value" strings or (path, value) pairs, see set_path) to every event find_events returns. Events that don't change are left out. Nothing is written when dry_run is set or any edited event fails check. Otherwise the files are written (and moved when start or id changed) and tree_check(root) runs, rolling back on problems (the trimmed app passes check_event_tree, which needs no JSONSchema). A bad key or value throws ArgumentError.

source
TangoKalender.edit_main — Function
edit_main(args; io=stdout, err=stderr, tree_check=validate_event_tree, render=styled_text) -> exit code

The edit subcommand. render turns lines of (text, face) segments into something printable: styled_text (StyledStrings) here, ansi_text in the trimmed tangoedit app, which also passes tree_check=check_event_tree. 0 = done (also when nothing matches), 1 = an edited event is invalid (nothing written), 2 = usage error. A first argument repeat runs repeat_main with the rest.

source
TangoKalender.repeat_events — Function
repeat_events(terms, rule; root="events", count=nothing, until=nothing, start=nothing, except=[], edits=[],
              today=today(), dry_run=false, tree_check=validate_event_tree) -> NamedTuple

Copy the template (repeat_template(terms)) to the dates of rule (recurrence_dates): after the template's date, or from start, until until, or count new events; without either, until 6 months after today. edits ("key=value", see set_path) apply to every copy. Dates that already have the event (same id or file) are skipped. Every copy must pass check; then the files are written unless dry_run, and tree_check(root) runs (rolling back on problems). Returns (template, keys, events, exists, excepted, written, errors), events as (file, event).

source
TangoKalender.repeat_main — Function
repeat_main(args; io=stdout, err=stderr, tree_check=validate_event_tree, render=styled_text, today=today()) -> exit code

The repeat subcommand (also tangoedit repeat …, through edit_main). 0 = done, 1 = a new event is invalid (nothing written), 2 = usage error.

source
TangoKalender.repeat_template — Function
repeat_template(terms; root="events") -> (file, event, keys)

The event to copy: the only event matching all terms (past ones included), or the latest one when all matches share one series, or the latest of the series a series: term names exactly. ArgumentError otherwise.

source
TangoKalender.repeat_event — Function
repeat_event(t, d; series, today) -> Event

A copy of template t on day d: same times (offset recomputed for summer/winter time) and the same number of days between start and end, id <series>-YYYY-MM-DD, status scheduled, first_seen today and no verification or crawl dates.

source
TangoKalender.Recurrence — Type
Recurrence(unit, n, nth, weekday)

Every n weeks (unit=:week) or months (:month). Monthly rules fall on the template's day of the month (nth=0) or on the nth weekday (1 = Monday) of the month, counted from the end when nth<0 (-1 = last).

source
TangoKalender.recurrence_dates — Function
recurrence_dates(r, anchor; from, until=nothing, count=nothing, except=[]) -> (dates, excepted)

Dates of rule r on or after from, in step with anchor (the template's date: its weekday, day of the month and the phase of every-N rules). Stops after until or after count dates. Dates inside an except range go to excepted and don't count. Months without the day (the 31st) or the weekday (a 5th Friday) are skipped.

source
TangoKalender.event_card — Function
event_card(e::Event; before=nothing, width=terminal width) -> AnnotatedString

A compact terminal card of e, laid out like the web card: date and time, type chips (and AVLYST), price, title, venue, organiser/teachers/DJ/music, the start of the description, and id/series/links. With before (the event before an edit), every changed part is highlighted with the old value struck through after it, and changed keys that the card doesn't show get a «✎ key: old → new» line.

source

event_line(e::Event; width=terminal width) -> AnnotatedString

One line per event for match lists: short date and time, types, title, venue and id, in columns.

Lines of segments as a StyledStrings AnnotatedString.

New cities

TangoKalender.init_site — Function
init_site(dir; slug, city, site_url, repo_url, name="Tangokalender | <city>", version=package version) -> files

Start a new city's data repo in dir: site.toml, an empty events/ and venues.json, a Project.toml that pins TangoKalender version from CODE_REPO_GIT (SSH), workflows that call the package's reusable ones, Dependabot, the issue forms, a placeholder link-preview image, .gitignore and a README with the one-time GitHub setup. Refuses to overwrite an existing site.toml.

Write the issue forms for the current site into dir/.github/ISSUE_TEMPLATE/ (overwriting the package's forms, leaving other files there alone).

TangoKalender.geocode! — Function
geocode!(venues, events; fetch=_nominatim, retry=false, pause=1.0, today=Dates.today()) -> (added, failed)

Look up every event address missing from venues (normalised keys). Manual entries are never touched; addresses stored as not found (precision: "none") are only retried with retry=true. Network errors leave the address out, so it is tried again next time. pause seconds between requests keep within Nominatim's usage policy.
