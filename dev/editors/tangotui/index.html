Interactive editor (experimental)

Experimental, Julia only

TangoTUI is an experimental full-screen editor. It needs Julia (1.12 or newer) and a clone of this repository: it is not part of the stand-alone tangoedit download, because the terminal library it uses, Tachikoma.jl, can't be compiled into one. The screens are in Norwegian only for now. How it looks and works may still change; for anything that matters, check the result with git diff before you commit.

TangoTUI edits one event at a time in a form, so you needn't know field names, JSON or event ids:

  • It starts on a list of the upcoming events. Type to search, as on the web page, and open an event with ↑/↓ and Enter.
  • Every field is shown with its current value. Fields with a fixed set of values (type, status, music, text language) open a pick list, so only allowed values can be chosen.
  • A preview card shows the event as the site will, with changes highlighted and the old value struck through.
  • When you save a change to a date that has later dates, it asks whether the change applies to them too, but never to another organiser's events.

For changes to many events in one go, or without Julia, use tangoedit.

Set up and start

In a clone of your city's data repository (the folder with events/ and site.toml), with this repository cloned at PATH:

julia --project=PATH/TangoTUI -e 'using Pkg; Pkg.instantiate()'    # once, and after updating PATH

julia --project=PATH/TangoTUI -m TangoTUI                    # the list of upcoming events
julia --project=PATH/TangoTUI -m TangoTUI --all              # … including past events
julia --project=PATH/TangoTUI -m TangoTUI edit otra-2026-11-02     # straight to one event
julia --project=PATH/TangoTUI -m TangoTUI new                # a blank form
julia --project=PATH/TangoTUI -m TangoTUI new series:otra    # a copy of the series' latest event, on a new date

edit takes the same search terms as tangoedit (series:otra, type:class, venue:sentralen). When several events match, or none, it opens the list searching for them.

The list

Key
letterssearch: every word must match, in the title (any language), venue, address, organiser, DJ, teachers, description, date, weekday, id or series; key:text searches one field
↑ ↓, PgUp PgDn, Enterchoose an event and open it
Ctrl-Aalso show past events (press again for upcoming only)
Ctrl-Na new, blank event
Ctrl-Ka copy of the selected event on a new date (the date field opens first)
Escclear the search; on an empty search, quit

The form

Key
↑ ↓, Tab, PgUp PgDnchoose a field
Enteredit the field; Enter saves it, Tab saves and goes to the next, Esc cancels
in a pick list↑ ↓ to move, Space to tick (where several are allowed), Enter to choose
Delclear the field
Ctrl-Ssave the event
Escback to the list (asks first if there are unsaved changes)

A field that breaks a rule of the event format is marked ! in red, with the reason below the form; saving is refused until it's fixed. Some fields take short forms:

  • Dato: 2026-11-04 or 04.11.2026. A new date moves the end along, and the file moves to the new date's folder.
  • Starttid: 20:00; empty for events without a time (festivals).
  • Slutt: 23:30, or a time before the start for after midnight (01:30); 2026-11-08 for an event over several days, or 2026-11-08 18:00. Summer and winter time are handled.
  • Lærere: names separated by commas. Pris: whole kroner (150 or 150 kr), or «betal det du kan» for pay what you can, optionally with a suggested amount («betal det du kan, 100»).
  • Tittel: the event's own name, without the organiser (it has its own field and is shown in the list).

A new event gets the id <series or title>-YYYY-MM-DD, like events from the submission forms.

The same change on several dates

When you save a change to an event that has later dates, TangoTUI asks:

  • a: all later dates of the event's series, from this date on;
  • u: all later events of the search you opened the event from (offered only when the list was filtered);
  • d: only this date;
  • Esc: cancel; nothing is saved.

Only the fields you changed are copied, never the date. A new start or end time is set on each date with the right summer or winter time, and an end some days later keeps its length. The question lists the dates, and marks those that had their own value (for example a special price) that would be overwritten.

Guardrail: only events with the same organiser as the event you edit are changed. Events by other organisers in the series or the search are left alone and listed as skipped. All files are written together: if the check of the event tree fails, none of them are.

After saving

Saving writes the event files in their own key order and sets last_verified to today. TangoTUI never commits: when you quit, it lists the files it saved. Review and commit them as usual:

git diff
git add events && git commit -m "Onsdagsmilonga: ny pris fra 28. oktober"
git push
